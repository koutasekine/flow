# フローチャート — 記号一覧・接続点・検査規則

出典はすべて JIS X 0121:1986(JISC 閲覧版)。条項番号は JIS のもの(対応国際規格 ISO 5807:1985 は章番号が 1 ずれる: JIS 8 章 = ISO 9 章)。

## 1. 使う記号(プログラムフローチャートで用いる記号、10 章 記号用途一覧)

| 記号 | 条項 | 形(実装) | 入口 | 出口 |
|---|---|---|---|---|
| 端子 | 8.4(2) | 両端半円の長丸 80×40 以上(図内で処理と同じ幅) | 上辺中央 | 下辺中央 |
| 処理 | 8.2.1(1) | 長方形 80×40 以上(2:1。文字に応じて図内で統一して広げる) | 上辺中央 | 下辺中央 |
| 定義済み処理 | 8.2.2(1) | 長方形 + 左右内側の縦線(内側線は端から幅の 1/12) | 上辺中央 | 下辺中央 |
| データ | 8.1.1(1) | 平行四辺形(上辺が右へ 10 ずれる)80×40 以上(図内で処理と同じ幅) | 上辺中央 | 下辺中央 |
| 判断 | 8.2.2(4) | ひし形、幅:高さ = 1.8:1(最小 108×60。図内で同寸。長い条件は最大 3 行に折り返す) | 上頂点 | 下頂点(Yes)、右頂点(No)。特例では右頂点(Yes = break)または左頂点(Yes = continue)と下頂点(No) |
| 結合子 | 8.4(1) | 円 直径 28 | 上(出結合子) | 左または右(入結合子) |
| 注釈 | 8.4(3) | 角かっこ `[` + 対象記号からの破線 | — | 対象記号の右辺中央から。ひし形では右上辺の中点から、出口の線とラベルより上に置く |
| 線 | 8.3.1(1) | 直線、水平・垂直のみ | — | — |

プログラムフローチャートで使えるがこのツールが生成しない記号: 準備 8.2.2(3)、並列処理 8.2.2(5)、ループ端 8.2.2(6)、破線 8.3.2(3)(注釈の破線としてのみ使用)、省略 8.4(4)。
プログラムフローチャートに用途一覧の星印がない記号(記憶データ、個別データ記号 8 種、手作業、制御移行、通信)は使わない。

寸法は規格に規定がない(9.1(2) は「形を手本にし、角度を変えず、一様な大きさ」のみ)。上の比(処理 2:1、判断 1.8:1)は JIS の図(10 章 記号用途一覧)を画素計測した値に合わせた実装値。

## 2. 配置規則

| 規則 | 条項 |
|---|---|
| 標準の流れは上→下、左→右。分岐(No)は右へ出す | 9.2.1(1) |
| 矢印は線の終端 1 か所だけ。記号に入る線は標準方向でない区間(上向き・左向き)を含むときだけ入口に付け、横から合流する線は合流点に付ける。縦に合流する幹の線と、標準方向だけの線には付けない。線は角で終わらせず次の記号まで延ばす | 9.2.1(2)、8.3.1(1) |
| 線は交差させない | 9.2.1(3) |
| 合流は T 字で入れる(交差に見えないようにする) | 9.2.1(4) |
| 線は記号の上から入り下から出る。流れ線の延長線は記号の中心を通る(ひし形は頂点から出入り) | 9.2.1(5) |
| 線は直線で、記号は等間隔に置く | 9.1(1) |
| 記号の形・角度は変えない。同種の記号は図の中で同じ大きさ(最も長い文字に合わせて幅を 20 刻みで統一して広げる) | 9.1(2) |
| 記号内の文字は左から右へ書く(機能記述) | 9.1(3) |
| 記号識別子(行番号)は記号の左上 | 9.1(4) |
| 関数は別の図。開始の端子に「f(引数)」、終了の端子に「f 終了」 | 9.1(6) の詳細表現の形、8.4(2) |
| 判断の各出口に条件(Yes / No)を書く | 9.3.1(2) |
| 複数出口は記号から複数本の線を出す形 | 9.3.1(1)(a) |
| 線の中断(結合子)は交差を避ける必要がある場合と、図が 2 ページ以上に及ぶ場合に限る | 9.2.2(1) |
| ページ分割時の結合子に注釈記号でページ参照を付けてもよい(設定。既定は付けない) | 9.2.2(2) |
| 対応する結合子は同じ一意な名前 | 8.4(1) |

## 3. 内部検査(配置結果に対して機械的に検査する。利用者の操作では規格外の図を作れないので画面にはボタンを出さず、ツール自身の不具合検出と、break/continue の直線化で交差が出たときの結合子への切替判定に使う。問題が出た場合だけ左下に表示する)

| 検査 | 条項 |
|---|---|
| すべての線分が水平または垂直 | 9.1(1) |
| 線の端点が、記号の定義済み接続点(1 章の入口・出口)か、他の線上(合流点)にある | 9.2.1(5) |
| 逆向き区間を含む線が記号に入るならその入口に矢印、横から合流する線なら合流点に矢印がある。終端以外に矢印がない。逆向き区間を含む線が記号にも合流点にも達していない(角で終わる)ことがない | 9.2.1(2) |
| 線分同士が交差していない(端点を共有しない直交線分の交点がない) | 9.2.1(3) |
| 線が記号の内部を通っていない | 9.2.1(5) |
| 判断の出口に条件ラベルが 2 つ以上ある | 9.3.1(2) |
| 出結合子に同名の入結合子がある | 8.4(1) |
| 処理・データ・端子・定義済み処理の高さが 40、幅が 20 の倍数 | 9.1(2) |

検出できないもの(解析で確定): 記号内の文字が機能記述として適切か(1.1(4) により規格は用字用語を規定しない)、注釈の破線が他の線をまたぐこと(破線は検査対象外)、文字が記号からはみ出すこと(幅は文字幅から計算するが、フォントの違いで数 px の差が出る)。

## 4. 自動テスト(test/)

- `test/run.mjs`: `test/samples/*.py` を読み込み、パース → 配置 → 内部検査(問題 0 件)→ A4 縦のページ分割後も各ページが内部検査を通り結合子が対になっていること → 往復変換(テキスト → AST → テキスト → AST → テキスト が一致)を確かめ、`test/out/` に SVG と PNG を書く。`test/errors/*.py` は `# expect: 行番号` のエラーになることを確かめる。
- `test/gui.mjs`: GUI の構造化編集(選択・文字変更・挿入・削除・else の追加削除・注釈)がテキストに反映されることを確かめる。
- `test/io.mjs`: JSON / SVG / PNG / .py の保存と、JSON / SVG / .py からの再読込を確かめる。
- 実行: `cd test && node run.mjs && node gui.mjs && node io.mjs`(Node 18 以上と `playwright` パッケージ、Chromium が必要。`PW` 環境変数で playwright のパスを指定できる)。
